# 15 — Verificación y confianza

## Objetivo

Reducir perfiles falsos y mejorar la información disponible para contratar, sin presentar la verificación como una garantía absoluta del resultado del servicio.

## Principios

- Solicitar únicamente información necesaria.
- Proteger documentos y datos sensibles.
- Explicar qué se revisó y qué no se revisó.
- Mantener trazabilidad de decisiones.
- Permitir corrección y nueva presentación cuando corresponda.
- Evitar discriminación por razones ajenas a requisitos legítimos del servicio.

## Niveles propuestos

### Cuenta confirmada

La persona confirmó al menos un medio de contacto. No equivale a proveedor verificado.

### Perfil profesional completo

El proveedor completó descripción, categorías, zonas y datos obligatorios.

### Identidad revisada

Un administrador revisó los documentos exigidos por la política vigente.

### Información profesional revisada

Cuando una categoría requiera permisos, certificados o evidencia adicional, se registra qué documento se revisó y su vigencia.

El MVP puede comenzar con un distintivo único de **Proveedor verificado**, pero internamente debe conservar qué comprobaciones sustentan ese estado.

## Información provisional a solicitar

La lista exacta deberá validarse según normativa boliviana y tipo de servicio. Como base conceptual:

- Nombre legal.
- Documento de identidad.
- Fotografía o comprobación de titularidad cuando sea justificable.
- Teléfono confirmado.
- Zona de operación.
- Categorías y experiencia declarada.
- Certificados o licencias solo cuando sean relevantes para la actividad.

No se almacenarán documentos adicionales por costumbre si no existe un propósito claro.

## Flujo administrativo

1. El proveedor completa su perfil.
2. Lee el aviso de privacidad y requisitos.
3. Carga la información solicitada.
4. Envía la solicitud.
5. El sistema bloquea ediciones críticas mientras está en revisión, salvo corrección controlada.
6. Un administrador revisa y decide: aprobar, observar o rechazar.
7. El proveedor recibe resultado y motivo general.
8. Los cambios futuros relevantes pueden iniciar una nueva revisión.

## Información pública

Puede mostrarse:

- Nombre profesional.
- Categorías y zonas.
- Estado de verificación.
- Reputación y cantidad de trabajos.
- Descripción y experiencia declarada.

No debe mostrarse públicamente:

- Número completo de documento.
- Fotografías de documentos.
- Dirección particular del proveedor.
- Notas administrativas.
- Datos usados exclusivamente para seguridad.

## Revocación y renovación

La verificación podrá observarse, vencer o revocarse cuando:

- Cambien datos esenciales.
- Venza un documento relevante.
- Existan inconsistencias comprobables.
- Se detecte suplantación o falsificación.
- Una medida administrativa justificada lo requiera.

La revocación debe registrar actor, fecha, motivo y evidencia disponible.

## Mensaje al usuario

El distintivo debe acompañarse de una explicación similar a: “La plataforma revisó información seleccionada de este perfil. Esto no garantiza el precio, la calidad ni el resultado de un servicio.”

## Pendientes

- Requisitos legales por categoría.
- Proveedor externo o proceso propio para validar identidad.
- Tiempo de conservación de documentos.
- Procedimiento de apelación.
- Renovación y vencimiento por tipo de documento.
